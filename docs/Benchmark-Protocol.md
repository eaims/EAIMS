# EAIMS Benchmark Protocol — Draft v0.2

EAIMS v0.2 publishes a benchmark-ready protocol but contains no real benchmark dataset.

## Eligibility

Include only assessments naming an EAIMS version, scope, assessment type, sector, organization-size band, geography band, assessment date, completeness, confidence distribution, and modifications. Exclude unverifiable, marketing-selected, incomplete, incompatible, or duplicate submissions.

## Privacy

Collect the minimum necessary data. Use pseudonymous organization IDs, separate identity keys, access controls, retention limits, deletion procedures, and aggregation thresholds. Do not publish a segment with fewer than five organizations. Never publish evidence content, personal data, security details, or organization-level scores without explicit authorization.

## Comparability

- Separate self, facilitated, and independent-review results.
- Do not combine materially different EAIMS versions without a published normalization method.
- Disclose exclusions, weighting profiles, and local modifications.
- Report median, interquartile range, sample size, and confidence coverage; do not rely only on averages.
- Segment only when sample size and disclosure risk permit.
- Distinguish a sample description from population inference.

## Quality controls

Use duplicate detection, range and schema validation, anomaly review, assessor conflict disclosure, and an immutable submission log. Pre-register analytical rules before viewing outcome distributions.

## Publication

Every benchmark release must publish methodology, period, sample construction, exclusions, missing-data treatment, version, uncertainty, limitations, conflicts, funding, and correction/withdrawal procedures.

## Prohibited practices

No fabricated submissions, pay-to-rank treatment, sponsor score advantage, silent cherry-picking, re-identification, cross-version comparison without disclosure, or claims of global representativeness without a defensible sample.
